## 3. 开发总路线与硬门禁（以依赖为准，不逐项返回网页端）

### A. P0：保护现有项目和业务数据（必须先满足安全边界）

按签收顺序：**P0-01 → P0-02 → P0-04 → P0-03 → P0-05 → P0-06 → P0-07**。

1. **P0-01** 先识别当前 Git 状态、未提交/未跟踪资源、既有删除、实际部署配置、数据库环境、WAL/SHM/并发写入、AGENTS/manifest/两份权威文档。只读核查；不整理或覆盖资源。manifest 的 collaborationRevision 变更已追溯内容与完整性关系，**触发进程/授权来源未核实**，不得擅自回滚。
2. **P0-02** 如要在**真实环境**获取一致性备份并隔离恢复，先单独得到用户对具体 DB 环境的授权；不能只复制活跃 SQLite 主文件，不能展示凭据/聊天正文。未得到授权时，可以先使用**纯虚构隔离数据库**验证备份恢复逻辑，但真实数据保护闸门仍未通过。
3. **P0-04** 写出安全拒旧接口的代码与隔离测试：旧 POST /api/user/sync 在任何 settings/Key/声音库/会话写入前，针对**已认证、语法合法的 JSON** 统一 409 SYNC_UNSAFE；包括空对象，不能先被 SyncPayload 完整体验证成 422（N1）。旧 /api/chat 在新的安全 turn 尚未可用前进入 423 只读维护，且不可调用供应商；不要产生“聊成功但不保存”。**实际服务切换/维护需要单独授权**。
4. **P0-03** 设计显式版本化、可重复执行、失败可见的最小 schema/revision 迁移入口，隔离旧 init_db create_all/吞异常 ALTER 的风险；SQLite 每连接外键、CAS 事务和最小约束用虚构 DB 验证。**真实 schema 写入必须等真实备份可恢复 + 写冻结已授权且生效**；不得提前实施角色等 P1 迁移。
5. **P0-05** 新的局部 GET/PATCH settings 与独立凭据槽操作：不回显明文 Key，configured metadata 供新前端使用；PATCH 白名单、省略/null/空串明确、expected_revision 原子检查；custom_voices 传输为对象数组，不误清空旧 Key/其他设置/会话。
6. **P0-06** 改真实原生前端 hydration：首次 setTheme、hydrate 中 setTheme、saveSessions 不得误提交空整包；加载失败不上传空缓存；所有保存先检查 HTTP response.ok，失败保留草稿、显示真实错误；旧 localStorage 的 Key 在确认安全迁移后才清退，失败不得清空服务器凭据。
7. **P0-07** 使用虚构用户与依赖模拟证明：空本地列表不减服务器已有 N 会话；拒旧请求零业务写；PATCH 主题仅改主题 + revision；并发修改 409 保留草稿；401/409/422/428/423/500/网络失败不显示成功；恢复后原始 ID/摘要一致；回滚永不重开危险旧同步。

**安全开关顺序禁止变更**：真实数据库变更不得早于已验证可恢复备份与有效维护/拒写。P0“代码写好”与 P0“真实环境通过”必须分别记录。P0 保护性维护结束后，旧聊天仍然维护，直到 P1b 安全 turn 写入完整通过且获批准切换，不能提前开放危险写入口。

### B. P1a：角色、默认角色、旧会话与稳定消息 ID

- SQLAlchemy 实体/迁移/约束建立账号→角色→会话→消息稳定链路；旧 session ID、原始 messages JSON、音频引用和未知字段必须保留，并用**持久的 (session_id, legacy_index) → message_id** 映射，重跑迁移保持 ID；原时间不明为 null，不伪造发送时间。
- 迁移为每账号创建恰当默认角色，严控跨账号/跨角色访问，报错记录阻断而非默默跳过坏数据。真实迁移需要单独许可；虚构隔离库可先实施验证。
- 角色列表/创建/编辑、切换、默认、回收站/恢复/二次确认永久删除；D1 允许零活动角色；D2 角色最近使用排序，**纯 GET、轮询、后台任务不得更新使用时间**，null 最后，稳定平局裁决。D3 会话删除后素材来源状态安全处理。
- 自然接入**可操作的真实角色工坊和顶部快速切换**；顶部仅切换，不出现创建/管理入口。角色工坊与学习中心是主工作区，不额外放“返回聊天”按钮。

### C. P1b：服务端聊天 turns、幂等、状态查询和取消

- 扩展 /api/v1/chat/turns 等冻结路径；服务端使用 JWT→账号→role/session 归属，服务端装配上下文；不能信任前端 SOUL/Memory 全文作为鉴权依据。
- 用户消息/turn 与 attempt 持久化，POST 重放同键同请求返回同一状态，异请求同键 409 IDEMPOTENCY_CONFLICT。处理中重复 POST 不额外创建消息、不重复调用供应商。
- 确定尚未下发与确定失败才可按冻结协议**由用户显式 retry**；下游结果未知时不能自动再次调用可能计费的请求；外部调用不持有 SQLite 长写事务。
- 取消、完成、超时、崩溃恢复、迟到结果处理按 T1 状态机；角色/会话删除后不能复活消息或音频；前端刷新后以服务端最终状态为准。
- 提供一个真实可操作的文本发送、查看、刷新/恢复与取消闭环（可用模拟 LLM 测试），不得只留 API 文档。满足安全切换与授权条件之后才解除 P0 聊天维护状态。

### D. P1c：SOUL、Memory、版本与明确禁记

- 单个 SOUL 自由文本编辑框；内部 user_text + ai_growth_notes 等实现细节必须保持可见内容、成长开关、用户编辑、去重及历史恢复的冻结语义。不能因用户只改开关就把 AI notes 固化为用户基线；结构变更批次为 **P1c**（N3 勘误）。
- Memory 按角色分离、可编辑文本与版本；自动整理采用阶段性 + 会话结束补充，任务提交使用最新角色存续、revision、禁记/抑制规则复检，防止旧后台候选迟到覆盖。
- 显式禁记与稳定来源关联；历史恢复和模型上下文过滤有效禁记；语义改写不可能保证绝对零出现，使用有限测试集合、保守屏蔽与失败拒绝。数据库恢复不能绕过备份之后有效的禁记记录。
- 敏感信息不写入可公开日志，不收集 Key、医疗等敏感内容作为默认长期记忆；严格区分用户确认与 AI 自动生成。
- 角色创建如同步初始化空 Memory，则 revision=1；冻结例子 memory_revision:0 与正整数规则矛盾（N3），**实施该 API 前作限域自洽修正并测试**，不要静默保留两个不兼容含义。

### E. P1d：声音绑定、降级、音频权限和原版视听

- 角色 voice_binding 仅三种合法形状：inherit / elevenlabs（voice_id + 可选 TTS model）/ edge（edge_voice），按每个回合起始解析并冻结有效声音，不混用模型选择；角色不存密钥。
- 账号默认→Edge→browser_required 的合法降级路径，区分 TTS 禁用、服务合成 ready、浏览器能否播放、静音、手动播放和取消。供应商错误区分 Key 失效、限流、配额、超时，不把供应商 401 当应用 JWT 过期。
- 音频必须按账号/角色/会话/消息归属鉴权。若采用 Bearer fetch→Blob→object URL，仅持久化真实音频资源标识，不持久化临时 blob URL。
- **保留原版** HTML/CSS 渐变/四层环/SVG 噪声/星云与真实 HTMLAudio + Web Audio 频谱及字幕逻辑；V5.2 的 Orb 是占位示意不能覆盖。浏览器 speechSynthesis 缺少真实频谱时用中性状态，不伪造音量响应。
- 统一控制 HTMLAudio、浏览器朗读、录音、字幕、切角色/会话、取消及迟到回调；异步任务绑定账号/角色/会话/turn，避免跨角色播放。

### F. P1e：轻量学习中心

- 账号级共享多语言词库（含语言新增、移除和单语清空确认）、词条学习三状态、收藏句子与原消息关联；服务端验证真实 role/session/message 来源链。源聊天删除时执行 D3 且不可旁路读取私聊。
- 主动选词需有消息语言判定/用户确认路径，不可直接沿用学习中心全局语言作为消息语言；译文与原文选区不能混淆。
- 手动输入、批量粘贴、TXT、真正 CSV 引号/多行解析；先预览有效/重复/错误，再按合法行确认。幂等重放优先于过期判断，预览单次消费，不用新键重复使用，commit 时再次去重、不覆盖已收藏释义/状态/来源。
