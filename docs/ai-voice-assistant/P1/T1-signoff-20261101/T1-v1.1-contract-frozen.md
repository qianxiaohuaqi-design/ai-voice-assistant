## 1. P1 产品边界与排除范围

### 1.1 P1 正式范围（产品决定已确认）

1. **多角色。** 用户可创建/编辑/切换角色；角色独立 SOUL、Memory、声音与会话；支持默认角色、回收站、恢复与二次确认永久删除。右上角色菜单只切换角色，创建/管理在角色工坊。
2. **SOUL。** 每角色只有一个面向用户的连续自由文本编辑框；AI 可在受限范围内渐进成长但不能自行改变用户确立的核心身份与性格；用户可关闭成长、查看/恢复版本。
3. **Memory。** 按角色独立、阶段性及会话结束后自动整理、可编辑与查看版本；用户明确禁止记忆时，历史恢复、候选提交和可提供给模型的上下文必须过滤，并承认语义遗忘不能保证绝对零再出现。
4. **声音。** 角色声音绑定与账号服务商凭据分离；完整保留原版 ElevenLabs/Edge-TTS/浏览器朗读及可视化；处理合成失败、浏览器拦截、切换与取消。
5. **轻量学习。** 每角色独立学习开关，**默认关闭**，角色详情与聊天顶栏小图标双入口；账号级多语言词库、三种手动状态、主动选词/收藏句子、手动添加、粘贴/TXT/CSV、预览去重、按语言清空与素材来源保留。
6. **导航与设置。** 个人资料/个性化/系统设置/使用指南职责区分；保留模型 API、聊天模型选择、翻译、声音库及会话同步能力；使用指南无“模型资费/耗费”表。桌面二级弹窗居中，手机可以使用底部弹窗。
7. **迁移保护。** 旧账号、会话原始消息和旧资源 ID 可追溯；共享词句在角色永久删除后仍保留并显示“来源角色已删除”。

闪卡/间隔重复、考试评分与排行榜、重型课程体系、全量自动抽取学习素材、真实麦克风频谱输入可视化（非原有能力）、词级精确字幕对齐、流式 Token 输出、独立 STT/TTS/重生成 API、Redis/向量数据库、Vue/React 重构、云端自动部署和原生移动 App。保留旧有能力不等于必须为旧能力新增独立 API。

## 2. 通用接口、字段、权限与错误契约

### 2.1 版本、鉴权、ID、时间

- 新路由前缀 `/api/v1`；旧路由仅按 §3 安全过渡。新业务接口使用 Bearer JWT，服务器从 Token 获得 `user_id`，**不接受客户端传入的 user_id 作授权依据**。
- 新 `role_id`, `message_id`, `turn_id`, `word_id`, `sentence_id`, `revision_id`, `audio_id`, `preview_id` 使用不复用的 UUID；`client_turn_id` 和 `Idempotency-Key` 为客户端产生的 UUID、服务端校验；旧 `session_id` **原样保留**（新会话可以使用 UUID）。账号 `user.id` 延续旧数据类型。
- 时间 UTC ISO-8601，未知原始消息时间必须是 `null` 并携带 `timestamp_source:"unknown"`，不能用迁移时刻冒充发送时间。`created_at` 与 `received_at` 可区别记录。
- 业务实体 `revision` 为正整数、单资源单调递增；常用 `expected_revision` 必传，缺失返回 `428 PRECONDITION_REQUIRED`，不匹配返回 `409 REVISION_CONFLICT`。创建时 revision=1；只读不加 revision。`PATCH` 为明确字段局部修改，不是隐式整包覆盖。
- 列表 `limit` 默认 30、最大 100，`cursor` 不可猜测、不越权；统一 `{items,next_cursor}`。会话内消息按 `ordinal ASC,message_id ASC` 稳定排序，基于游标翻页。
- 所有 JSON 响应含 `request_id`；**204 No Content、二进制音频和被流式传输的静态资源无 JSON body**，可把 `X-Request-ID` 放 HTTP 响应头；即使 `request_id` 不可生成，也不得因此拒绝安全拒写。
- 服务器将消息/资源读取与当前 Token 账号关联；带 `/roles/{role_id}/...` 的路由验证后续子资源也属于该角色，否则 404。只含 `session_id`/`turn_id`/`audio_id` 的路由按数据库资源归属**推导 role_id**，先验账号所有权，而不是把“浏览器当前选中的角色”当作后端可知状态。同账号有权管理其所有角色，但不能将一个角色的上下文注入另一个角色；给出显式 `role_id` 时与推导结果不符返回 404。
- 学习素材的 `source_*` 是可见来源元数据，**不是授权读取原聊天的凭据**。学习 API 不返回其他会话消息正文，来源的读取仍走正常会话鉴权。

### 2.2 版本号作用范围（明确资源字典）

| 资源 | revision 作用域 | 变化时递增 | 不递增 | 写入要求 |
|---|---|---|---|---|
| `/me` | 单用户资料 `profile_revision` | 昵称、头像引用 | 读取、其他资源更新 | PATCH `expected_revision` |
| `/settings` | 单用户账号设置 `settings_revision` | 任何设置 PATCH、凭据 PUT/DELETE、声音库的变更 | 聊天/角色/词库更新 | PATCH/凭据写操作均传 `expected_revision`，同一事务比较和更新 |

| `VocabularyEntry` | 单词条 `word_revision` | 状态/释义的显式 PATCH | 读取/重复导入跳过 | PATCH `expected_revision`，缺失 428 |

### 2.3 PATCH / null / 空字符串约定

- **省略字段**：不修改。`expected_revision` 不属于业务字段，写入不可省略。
- **显式 `null`**：仅 `display_name` 的可选头像引用 `avatar_ref`、`model.base_url`、`source_*` 等在字段表明确允许的可空项可清空；其他非空业务字段（主题、模型、voice_binding、声音库、语言状态等）返回 422。`display_name` 本身不可为 null/空白。
- **空字符串**：普通文本编辑 `SOUL.text` 和 `Memory.text` 允许 `""`（Memory 清空不等于永久禁记）；名称、模型名、服务商、语言、Voice ID 不允许 `""`。`model.base_url:""` 与 `null` 同义恢复自动选择；凭据的空字符串**一律 422**，撤销必须 DELETE。不得将空字符串当“没改”，更不得当“清空其他设置”。
- **嵌套对象 PATCH**：`settings.model`,`settings.tts`,`settings.translation`,`settings.appearance`,`voice_binding` 均为严格白名单；只有出现在提交对象中的子字段被修改（例外：`voice_binding` 为完整鉴别联合体，见 §4.7）。未知字段返回 422 而不是猜测忽略。
- **`custom_voices`**：新接口对象数组、整体替换，不是字符串；旧数据库及旧 GET 的 JSON 字符串按 §3.4 转换。`null`、混合类型、重复条目返回 422；未传不动，空数组 `[]` 为用户明确清空列表（会话、角色绑定不被级联删除）。

### 2.4 错误结构、状态码及旧接口例外

成功 JSON 使用显式结构，异常 JSON 固定为：

```json
{"error":{"code":"REVISION_CONFLICT","message":"已有更新，请检查后重试。","details":{"current_revision":8}},"request_id":"req-001"}
```

| HTTP | `error.code` | 含义与 UI 行为 |
|---|---|---|
| 400/422 | `VALIDATION_ERROR` | 字段无效，不写入；保留草稿 |
| 401 | `UNAUTHORIZED` | **本应用** JWT 未登录或失效；清理登录态只依据本应用认证结果 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在/无账号权限/明确角色不匹配，不泄漏资源存在性 |
| 409 | `REVISION_CONFLICT` | expected_revision 旧；保留修改草稿，展示当前版本号 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同键不同请求正文，不创建第二次任务 |
| 409 | `STATE_CONFLICT` | 资源生命周期/不允许状态转换/预览过期等 |
| 409 | `SYNC_UNSAFE` | 危险旧整包写入被安全阻止；业务数据零写入 |
| 423 | `READ_ONLY_MAINTENANCE` | 保护窗口内禁止发聊天/写业务，提示用户聊天不会保存，**不调用供应商** |
| 428 | `PRECONDITION_REQUIRED` | 需要版本/前置条件，不执行写入 |
| 429 | `RATE_LIMITED` | 配额/频率限制；可给安全 `Retry-After`，不含供应商密钥 |
| 502 | `PROVIDER_AUTH_FAILED`, `PROVIDER_QUOTA_EXCEEDED`, `MODEL_UNAVAILABLE` | 供应商身份/配额/服务错误；**不把供应商 401 当本应用 JWT 过期** |
| 503 | `PROVIDER_TIMEOUT`, `PROVIDER_UNAVAILABLE` | 下游超时/不可用；若调用结果未知，转为 `outcome_unknown` 不自动重试付费请求 |
| 500 | `INTERNAL_ERROR` | 脱敏错误；不能返回堆栈/SQL/供应商原始响应 |

旧路由 `/api/register`,`/api/login` 在过渡期可保留其历史 `detail` 文本，前提是删掉 traceback、凭据、内部路径；旧端接受此模式。旧 `/api/user/sync` 被安全拒写时优先返回标准 JSON **并可同时提供精简 `detail`** 以便旧 UI 展示；但旧缓存 JS 若没有错误处理，仅保证服务器安全拒写，**不能宣称旧界面已正确提示**。不承诺某个未经定义的旧最低客户端版本仍能完整写入；兼容只读能力的结束时间以实际发布与验证为准（§3.4），在 T1 不编造日期。

### 2.5 幂等、传输重放与不可判定的下游结果

- `(user_id, operation, idempotency_key)` 唯一并持久化原始请求规范化哈希、状态、响应结果引用；`ChatTurn` 另外约束 `(user_id,client_turn_id)` 唯一。
- **同键、同请求体传输重放**：原任务正在执行返回当前持久状态（202）；已结束返回原终态（200 或已记录的确定错误），不得重新生成用户消息、assistant 消息或再次呼叫第三方。
- **同键、不同请求体**：409 `IDEMPOTENCY_CONFLICT`，不执行。
- **尚未发出下游请求的确定性失败**：允许明确的主动 retry（§5.5），仍在相同 `client_turn_id` 下新增 `attempt_id`；原 user_message_id 不变，服务器必须确认前一 attempt 未发出。
- **已发出下游请求但结果尚未持久化、连接中断/进程崩溃**：`outcome_unknown`；服务器没有供应商侧幂等/查询能力，**不能自动重新发出付费调用，也不能保证不会重复计费**。UI 展示不确定情况并等待用户显式决定是否新发一轮。
- **已确认失败的下游请求**（例如已收到确定的错误码）可在同 turn 下通过**单独 retry 操作**创建新 attempt，且必须显式触发并经过状态许可；不重复写入原 user 消息。供应商返回 HTTP 错误不必然意味着“没计费”，因此 UI 不承诺此次重试无额外费用。
- `Idempotency-Key` 对已成功导入也遵循重放优先规则（§6.5）。本地数据库幂等只防本地重复写和**同键再次主动调用**，不能覆盖第三方已经处理但本地未知的外部窗口。

| `POST /api/models/fetch`, `GET /api/models` | 暂留；服务端查 Key | 静态模型列表/回退不等于模型可实际调用；不能依赖 localStorage Key |

| `POST /api/user/sync` | **P0 服务端默认拒绝全部旧整包写入** | 必须在设置/会话任一变动前返回 409，业务零写入，不存在默认 full-replace 例外 |
| `POST /api/chat` | P0 保护窗口内 423 只读维护 | 因旧聊天后续无法安全保存会话，不能允许模型调用后悄悄丢消息 |
| `GET /api/audio/{id}` | 审计所有权；不明归属一律拒绝无认证公开读取 | 新音频走受保护 `/api/v1/audio/{id}`，未知归属旧音频不暴露 |

**本版明确不采用未验证的旧整包客户端 full-replace 旁路。** 即便客户端添加 `X-Sync-Mode`、`If-Match` 也不授予整包替换资格。将来若要重新引入，必须独立升版定义服务端资格颁发/撤销、快照范围、revision、原子 CAS 与双主切换协议；它不属于 P0/P1 当前默认实施契约。

### 3.2 P0 旧同步“零写入”安全门禁

1. **首行安全门禁**：受保护的旧 POST 在认证、方法入口的最早位置判定禁止写入；鉴权解析可进行，但任何 user settings、API Key、声音库、会话 insert/update/delete、revision 更新都**不能发生**；不可先覆盖设置再拦截删除。
2. **成功条件是拒写原子性**：所有 `{}`、省略 `sessions`、`sessions:[]`、包含实际列表、带自制 `X-Sync-Mode`/`If-Match` 的旧 POST 都拒写；统一 409 `SYNC_UNSAFE`。预期无任何业务数据库变化，包括 `updated_at`。
3. **旧 GET 不作为新写入令牌**：不颁发 full-replace 许可，不接受客户端对旧 GET 快照的“自我声明完整”。
4. **旧路由兼容性是读和可解释拒绝，不是危险写入继续可用**：缓存旧 JS 若未检查非 2xx，无法保证旧 UI 出现正确提示；安全策略优先，必须限制该旧前端的操作入口/进入维护窗口并验证安全说明可见。
5. **内部静态资源/浏览器缓存**：缓存旧前端继续访问时，服务器强制拒旧同步/旧聊天写；必须有可验证的更新/强制刷新策略，但不假称旧 JS 自动升级。

**拒写 JSON（409）**：

```json
{"error":{"code":"SYNC_UNSAFE","message":"此版本的数据同步已暂停，为保护聊天记录请更新界面。","details":{"write_allowed":false}},"request_id":"req-sync-block-001","detail":"旧版整包同步已停用，请使用受支持的新界面。"}
```

### 3.3 过渡期聊天和设置开放状态（不得静默失存）

| 阶段 | 旧前端聊天 | 旧 POST sync | 新局部 settings | 新聊天 turns | 条件 |
|---|---|---|---|---|---|
| `P0 maintenance` | **423 READ_ONLY_MAINTENANCE**，发起前不调用模型/TTS | 409 拒写 | 只在 P0-05 测试/授权后对新客户端开放 | 不可用 | **默认过渡策略**；展示“只读维护，聊天暂不可保存” |
| `P0 safe-settings-ready` | 仍 423 | 仍 409 | 新客户端可读/局部写；老缓存客户端仍只读 | 不可用 | 账号配置局部更新经过隔离/前端验证 |
| `P1 turns-ready`（后续） | 旧版本仍维护/需升级 | 仍 409 | 可用 | 仅通过验证的受支持客户端可用 | 会话迁移/turns 测试通过、授权切换 |

- 未经过服务端安全写入口验证前，不允许旧 `/api/chat` 继续正常花费模型/TTS 调用，否则用户会误以为聊天已持久保存。`GET /api/v1/sessions` 可在迁移阶段只读，但 **P0 不实施新会话/turns**。
- 新前端在维护状态禁用发送/录音产生聊天写入，并明确说明；如果 UI 无法可靠提示，默认服务器拒调用仍是最低安全线。不能仅靠前端禁按钮保护。
- 登录、只读设置、历史会话浏览可在安全授权范围保持；操作敏感资源依旧经鉴权和归属校验。
- **恢复正常聊天的开门条件**：旧会话映射迁移 + 新 turn server-side 持久化 + 消息/音频/取消联调 + 正式用户授权；P0 结束本身不代表聊天写入恢复。

`GET /api/v1/settings` 200 完整示例（假数据，无 Key）：

```json
{
  "settings_revision": 7,
  "model": {"chat_model":"deepseek-chat","base_url":null},

  "request_id":"req-settings-001"

```

`PATCH /api/v1/settings` 请求：

```json
{"expected_revision":7,"appearance":{"ui_theme":"light"}}
```

`PATCH` 200 返回**完整脱敏 settings DTO**（形状同 GET，`settings_revision:8`）；不要只返回 `ok:true` 让 UI 猜状态。请求不能有 `credentials`、`sessions` 或未知字段。账号服务密钥不会因 GET 后 PATCH 其他字段而清空。

凭据变更：

- `PUT /api/v1/settings/credentials/{slot}`，`slot∈{llm_primary,elevenlabs}`：请求 `{"expected_revision":8,"secret":"nonempty-replacement-secret"}`；原子比较 `settings_revision`，服务端仅安全存储，不在响应、日志和 GET 返回密钥，响应 `200 {"settings_revision":9,"credential":{"slot":"llm_primary","configured":true},"request_id":"..."}`。
- `DELETE /api/v1/settings/credentials/{slot}`：请求 JSON `{"expected_revision":9,"confirmed":true}`（HTTP DELETE 接受 JSON body，客户端与代理部署前需验证）；成功 `204` 无 body，`X-Settings-Revision` 给更新版本、`X-Request-ID`；无效 precondition 428/409。删除某一槽不影响另一槽，也不改变聊天历史。
- PUT 空字符串/null 与 DELETE 不混用；GET 的 `configured` 是**准确字段路径** `credentials.llm_primary.configured` / `credentials.elevenlabs.configured`。 `last4` 不作为默认返回，减少元数据暴露。
- 凭据变更会递增 `settings_revision`，与其它设置 PATCH 使用同一并发 CAS，阻止跨设备丢失更新。
- **迁移切换策略**：先建安全 GET/PATCH/PUT/DELETE 与服务端 Key 解析；读取旧 DB 槽但不通过新接口明文回传；完成安全加载/真实元数据验证和新前端接线后才关闭旧 GET 明文兼容。过渡期有风险的旧 GET 应仅在已认证、版本受控及明确期限的窗口开放；**默认安全切换后旧 `GET /api/user/sync` 返回 426 `CLIENT_UPGRADE_REQUIRED`（不含 Key）**，旧 POST 始终安全拒写。不能以“旧网页继续可用”为由无限暴露密钥。没有确定发布日期前不承诺最小客户端版本或日历截止日；以实际发布门禁和验证回执作为退出条件。
- **浏览器本地旧 Key 缓存**：受支持的新前端先从安全 `/settings` 验证对应 `configured`，并确认服务端用账号 Key 调用模型/语音的能力可正常读取，之后清除 `localStorage` 中旧 Key 缓存以及旧代码对 Key 明文的依赖。若 GET/凭据迁移失败，前端停留在安全维护/待修复状态，**不得清空数据库已存 Key，也不得在未验证后端可用时强制擦除用户浏览器仅存的 Key**；显示需用户手动校验/重配，禁止自动上传空值覆盖。
- 账号资料 `GET/PATCH /api/v1/me` 返回/修改独立的 `id,display_name,avatar_ref,profile_revision`；默认头像引用可 null，但昵称不可空。个性化单独 UI 仅修改 `appearance`；系统设置 UI 使用 model/tts/translation/credentials，后台可以共享 settings 资源，前端不能跳到同一面板。

### 3.5 新前端 hydration 和成功反馈

前端启动状态 `hydrating -> ready | load_failed | unauthenticated`：

- 首次 `setTheme()`、hydrate 内部再次 `setTheme()`、`saveSessions()` 都不得在 `hydrating` 提交写请求；本地空会话不视作服务端的真值。
- 在 P0 维护窗口，禁用聊天写和旧整包 sync。新前端设置 PATCH 只发送明确改动的白名单字段，不带 `sessions`；不可用旧浏览器缓存 Key 回填完整 settings。
- `fetch()` 必须检查 `response.ok` 和错误结构：断网、401、409、422、428、500 显示失败且保留待提交草稿；**只有服务端 2xx 确认后显示“已保存”**。
- 失败需支持显式重试，绝不因刷新、退后台、切换主题把空值或旧快照自动上送。

物理表拆分可由本地按真实 SQLAlchemy/SQLite 约束选择，但 **不变量必须落实到数据库约束、事务及测试**：

- `(user_id, client_turn_id)` 唯一；`(user_id, operation, idempotency_key)` 唯一；`(session_id, legacy_index)` 唯一且稳定；`(user_id,language_code,normalized_term)` 词唯一，`(user_id,language_code,normalized_text)` 句唯一；角色版本 `(role_id,revision_no)` 各自唯一；message_id、turn_id、audio_id 唯一。
- 活动默认角色对一个账号**最多一个**，事务内切换；无活动角色时至多零个。约束实现方式须在项目实际 SQLite 版本与 PostgreSQL（若使用）分别测试；不能假设高版本 SQL 功能均可用。
- 账号所有权、角色会话匹配、引用消息有效性在服务器验证并通过 FK/唯一索引尽可能强制；SQLite **每一个连接**打开 `PRAGMA foreign_keys=ON`，不仅仅在迁移连接上打开。
- 重要事务用数据库 CAS：`UPDATE ... WHERE id=? AND revision=?`，检查 affected-row=1，并在同一事务完成目标修改、revision 增量、相关消息/状态写入。外部网络调用期间**不得持有 SQLite 长写事务**。

### 4.2 默认角色、最后角色与零角色状态

已确认：新角色 `study_enabled=false`、独立会话/SOUL/Memory，创建默认角色用于迁移旧历史；回收站可恢复、永久删除二次确认。**恢复角色保持稳定 ID，但不因历史默认身份抢占现有默认**；若账户当前没有任何活动角色，恢复的首个角色成为默认。

**D1/D2 已由用户确认的正式规则**：

- 删除**非最后**默认角色（软删除）时，立即由服务器在同事务选择最合适的剩余活动角色为新默认：按该账号活动角色的 `last_used_at` 倒序，平局按 `created_at` / 稳定 ID 决定；目标角色和旧角色 `role_revision` 均递增。
- 删除最后一个活动角色允许，进入**零角色空态**：右上切换器显示“暂无角色”，主界面禁止发聊天、提示进入角色工坊创建角色；刷新、重新登录保持该空态，不能静默自动创建替补、也不能使用回收站角色发消息。
- 恢复角色到活动列表但不抢占现有默认；若恢复时没有任何活动角色，则自动将该恢复角色设为默认；创建第一个新角色也成为默认。
- **决议状态**：以上 D1/D2 产品行为已由用户明确确认。`last_used_at` 的稳定排序及平局裁决是为保证自动选择结果可预测而冻结的技术细节；仍须由本地在工程签收时验证可实施性，且不能提前修改代码或数据库。

### 4.3 回收站、永久删除、删除会话与学习来源

- **角色软删除**：`deleted_at` 非空，角色及其会话、SOUL、Memory 保留且只能通过回收站管理；新聊天/语音/自动记忆任务无法再执行。恢复保留所有 ID、会话、版本、声音，不自动过期。
- **角色永久删除**：必须已在回收站，用户在前端二次确认，取得绑定账号+角色+操作+短时有效期的一次性删除确认令牌，随后 `DELETE /api/v1/roles/{id}` 使用 `X-Deletion-Confirmation` + 幂等键；原子标记不可访问，并清理该角色私有会话、文字、声音引用及音频。外部音频物理清理可以异步但访问必须立即拒绝。关联词/句不删。
- **角色永久删除后的共享来源**：词句 `source_role_id/source_session_id/source_message_id` 均置 `null`，不留下可遍历的私有来源引用；展示 `source_status:"role_deleted"` → “来源角色已删除”，不保留原角色名；素材本身、释义、用户主动收藏的句子内容、状态不变。
- **仅删除会话**：词句仍保留；清空 `source_session_id`、`source_message_id` 和可进入原会话的深链，设置 `source_status:"session_deleted"`；如果角色仍活动且属于同一账号，必须保留 `source_role_id` 并动态展示当前角色名（角色后续永久删除时再清空），但**不得展示已删会话正文**。**D3 已由用户确认**：有效角色来源保留并显示，会话删除状态可见，学习素材不随会话删除而消失。
- **仅删除某条消息（若未来提供）**：已收藏词句仍保留，清掉 `source_message_id`，保留仍有效的 role/session；无权限通过素材接口回看已删消息。P1 不额外新增任意消息删除 UI，不把此技术规则当成新功能需求。
- **来源链创建**：来自聊天选词/句子的 POST 只接受 `source_message_id`（可附校验用 role/session id，但**服务端以消息为准推导**真实 session/role）以及用户选区、语言等字段。任何不同角色/会话拼接、过期或已删来源、非本人消息都返回 404/422，不能拼装为合法学习来源。纯手动输入的词句 `source_*` 为空且 `source_status:"manual"`。
- **来源不授权正文**：词句列表只展示用户主动保存的片段、释义、来源状态/角色标签；完整聊天内容只能由拥有该会话的用户经会话 API 读取，并且若带 explicit role 必须匹配。
- **不使用级联删除学习素材**：角色/会话 `ON DELETE` 不得级联到 `VocabularyEntry` / `SavedSentence`，删除前原子改写 nullable 来源，再删除私有资源。异步迟到的保存结果不能重新建立这些引用。

### 4.4 SOUL：单编辑框 + 用户基线与 AI growth notes 双层语义

**呈现规则（外部确定）：** 前端仅有一个可编辑的 `text`，后端结构可用 `user_text` + `ai_growth_notes`。在 GET 中的 `text=rendered_soul`，拼接使用固定、仅服务器拥有的成长段落边界，不允许同一 note 反复追加；在文本中展示成长内容但不要求用户理解后台拆层。

1. 创建角色：`user_text=创建时自由文本`（可用默认模板），`ai_growth_notes=[]`，`growth_enabled=true`（用户可手动关闭），`soul_revision=1`。
2. **仅切换成长开关且 text 未提交**：只改 `growth_enabled`、递增 revision 并生成元数据历史；**不改变 `user_text` 或 notes**，不能将 notes 固化为新基线。
3. 用户保存了**与当前服务端 rendered_soul 完全一致**的 `text`（即使同时改开关）：视为无文本修改，只改其他显式字段。避免无变动时把 growth notes 写成用户基线。
4. 用户明确编辑了合成全文（`text` 不同且 revision 匹配）：将**用户提交的完整可见文本**作为新的 `user_text` 基线，**清空旧 `ai_growth_notes`**，以防重复拼接；记录历史快照两层、文本和成长开关。此前 notes 若被保留在用户编辑文本中，视为用户主动认可的基线；不得继续再次附加。
5. AI 自动成长：只能更改 `ai_growth_notes`，对锁定核心身份/性格的规则作确定性校验并检查最新 revision；不确定则拒绝候选，不动原文。AI 不能直接写 `user_text`。
6. 版本快照记录 `user_text`、`ai_growth_notes`、`growth_enabled`、`rendered_soul` 和 actor；**恢复历史版本时同时恢复该版本的两层文本与成长开关**，形成新的 revision，不能悄悄保留当前 notes 再拼接。若恢复与当前禁记/安全策略冲突，安全策略优先并产生可说明的过滤结果。
7. GET/PATCH 必须使用 CAS；UI 409 保留草稿并提供刷新比较，不直接将远端长文本写入错误日志。

SOUL 的结构变更属于 P1b，不进入 P0。若用户编辑行为无法安全区分“文本原样/真实编辑”，按 `expected_revision` + 服务端规范文本比较，而非仅看前端输入焦点或 blur。

### 4.5 Memory：稳定来源关联、禁记与迟到后台任务

- `Memory` 是**一个角色一份连续文本**。普通编辑/清空/润色是普通 revision 更新；只有用户主动发起“不要再记/忘记”，经过明确确认才创建不可被普通历史恢复绕过的 `MemorySuppression` 规则。
- 建议内部从提取候选建立稳定 `memory_item_id`、`source_message_ids` 或 `source_turn_ids` 锚点；连续文本只是渲染层。不能依赖某段原文摘要 `rule_key` 就声称能覆盖所有同义改写。已有历史无 item ID 的文本必须保留可溯源快照和有限保守匹配范围；不确定来源不能当作“安全可复活”。
- 禁记 API 优先接受已知 `memory_item_id` + `source_message_ids`（必须属于角色）和 `expected_revision`；历史文本只有原文选区时提供 `selected_text` + `source_revision`，在服务端将其定位为当时的已知范围，确认无法唯一定位时拒绝自动禁记并提示用户明确选择；不得无条件存储原敏感句作为禁记索引。
- 禁记处理应在同一受控事务里：验证用户确认、角色仍活动/可操作、expected revision → 标记稳定来源或条目被抑制 → 从当前 Memory 过滤 → 更新 revision/历史可见快照。历史内容可以按最小必要存储保留以便审计，但对普通版本查看/恢复始终提供**已过滤**结果，不提供未过滤原文端点。
- **后续上下文与重提取**：已知被禁记的 message/turn、关联片段和其已建立的语义等价候选在摘要输入构造时先排除；进模型的角色 Memory 和历史提取输入也先过滤。对没有可靠来源关联且无法证明安全的候选，**保守拒绝自动写入**并记录脱敏待审状态，不让模型自评充当证明。
- **P1 有限测试集**：同条目原文、大小写/标点/空格变化、1–3 个常见同义改写、历史版本恢复、从同一来源再次提取、由旧任务迟到提交、从旧备份恢复后重新读取。至少覆盖三种不同的真实语法结构的**虚构数据**；不要求证明无限多语义改写的绝对遗忘。
- **后台竞态必测**：作业在禁记前已读取候选，禁记后才提交：提交事务必须再次检查 `role.deleted_at`、当前 `memory_revision`、当前 suppression 版本/规则与来源有效性。若已禁记则拒绝提交，不得依靠任务启动时的旧快照、旧 prompt 或“上游已经判断安全”。
- **数据库恢复安全门**：恢复旧快照后，若快照晚于的禁记记录仍有效，必须从隔离、安全持久的抑制变更日志/灾备副本重放其规则并验证，再恢复服务写入；若无法恢复完整有效禁记集，则**保持只读维护/禁止记忆回填与模型上下文使用**，不得让旧备份直接开放聊天或自动记忆。禁记日志可包含稳定来源 ID、规则指纹、时间、账号/角色关联；不能保存原始高敏秘密作为明文“删除黑名单”。
- **隐私保留界限**：禁记标识仅用于服务端抑制、严格最小化与访问控制；日志不输出原文/推断标签；用户 UI 能查看已禁记的状态与删除影响，但不暴露敏感原句。保存期与备份清理策略需在真正实施时按用户数据删除策略和部署环境单独核实，不能擅自宣布某个法定期限。
- **明确技术限制**：无法保证未显式关联的所有同义词、第三方留存和任何人类可能推理都“彻底忘记”。P1 承诺的是可测的稳定来源禁记、恢复过滤、重提取阻断和不确定候选拒绝，而不是未经验证的 100% 语义消失。
- 任务异步调度可使用当前 DB 的持久状态，不必 Redis。频率、队列公平性和最大重试由后续实现配置并记录，不能每条聊天无节制调用模型；自动任务失败不让聊天失败或覆盖编辑中草稿。

### 4.6 迁移、原始消息和数据库机制

1. **独立显式迁移入口**：不得以现有 `init_db()` 的 `create_all`/吞异常 `ALTER TABLE` 承担 P1 迁移；应用导入和测试运行不应自动执行写 schema。迁移有 schema 版本表、检查项、已应用状态、可重入步骤、出错立刻报告并停止；P0 仅允许设置保护相关的最小 schema/revision（§10）。
2. **备份先于迁移**：先核对实际 DB 目标/连接和活动写入，明确授权每个环境的备份；活动 SQLite 用一致性在线备份 API/受控停写方式，不简单复制主 db 文件（可能含 WAL）。隔离验证恢复，真实备份不提交 Git/不上传。
3. **旧账户默认角色**：每账号恰好一个迁移创建的角色，名称可为“默认角色”、学习开关关、SOUL 默认、Memory 空、声音 inherit。角色 ID 生成一次、持久化；重跑迁移重用已有迁移角色，不重复创建。
4. **旧会话**：保留原 `chat_sessions.id` 与原 `messages` JSON **字符串原样快照**、未知字段、音频 URL/指针和已有历史 ID（若存在）；为解析数组中的每个位置持久建立唯一映射 `(session_id, legacy_index)→message_id`，一旦建立不可变、重跑不得重新生成。旧数据缺 message_id 可新增，不应称“原始 message_id 已保留”；如实际原消息已有稳定 ID，也应保留到 legacy metadata 并建立关系。
5. **时间**：原始消息没有时间时，`created_at=null,timestamp_source:"unknown"`；允许单独记录 `migrated_at`，绝不冒充消息发送时间。
6. **归属**：旧会话加入迁移默认角色，不改原账号归属；原会话与消息顺序、正文、未知字段和摘要保持可验证一致。新角色不能自动继承旧私聊；角色归属回填期间允许临时 nullable，但新入口启用前所有可读会话明确归属。
7. **坏记录**：旧 JSON 无法解析时保留原字符串/摘要，隔离为待核查并阻断该账号的角色迁移切换；不得跳过异常消息后继续声称“迁移完成”。
8. **SQLite 约束**：所有迁移 SQL 在实际 SQLite 版本测试；需要重建表以增加 FK/唯一约束时在隔离副本上验证行数、旧未知字段和外键，禁止直接依赖新版本特性。
9. **新写入冻结及并发**：迁移窗口先有旧同步拒写与新聊天门禁，避免切换期间双写；revision CAS 与 DDL 变更不可只靠前端检查。
10. **上线/回滚分界**：切换前、仍冻结写入时可以恢复经校验的快照；切换后**只要已有新写入，就不得简单回滚旧快照覆盖增量**，必须先保全并核对增量，采用验证过的回放/正向修复。在不能可靠恢复增量时维持只读维护，不宣称回滚成功。
11. **恢复闸门**：核对代码和 schema 版本、账号与会话 ID 集合、原始消息逐会话计数/摘要、旧映射、索引与唯一约束、禁记当前有效性。**任何回滚都不得重新开放危险整包同步**。旧备份若缺少后续禁记规则，执行 §4.5 的补偿安全流程后才可开放写入。

### 4.7 角色声音绑定鉴别联合体与继承优先级

角色声音 `voice_binding` 是**一个完整替换的鉴别联合体**：

```json
{"provider":"inherit"}
```

```json
{"provider":"elevenlabs","voice_id":"example-voice-id","model":"eleven_multilingual_v2"}
```

```json
{"provider":"edge","edge_voice":"en-US-GuyNeural"}
```

字段约束：`provider∈inherit|elevenlabs|edge` 必须存在；`inherit` 不可含 `voice_id/model/edge_voice`；`elevenlabs` 必须非空 `voice_id`，`model` 可省略或 null，省略/null 表示在**开始当前回合时**继承账号 `tts.elevenlabs_model`，不可含 `edge_voice`；`edge` 必须非空 `edge_voice`，不可含 `voice_id/model`；未知子字段、无效 provider/空字符串返回 422。这里的 `model` **只指 TTS 模型，不是聊天模型**。

- Role PATCH 如未传 `voice_binding` 就不改；若传则整体替换 union，不能对子字段 partial PATCH 使其构成非法组合。
- 解析每轮 TTS 选择：账号是否允许合成 → 角色有效绑定 → 若 inherit 则账号 `tts.provider/voice_id/edge_voice/elevenlabs_model` → 如 provider 不可用进入 Edge 服务端兜底 → 再到 `browser_required`/仅文本。账号的 `tts.is_muted` 是默认自动播放偏好，不等同全局禁用合成。
- **有效声音配置在 turn 被接受并即将派发前解析并冻结为不含密钥的快照**（provider、voice_id、tts_model、edge_voice 与设置版本）；turn 中途用户切声音、删声音库条目或改 Key，不应静默改写本轮声音；真实服务调用前仍需验证当前授权凭据是否存在，且不给日志记录密钥。
- 删除账号自定义声音**声音库条目**只删 UI 管理列表引用，不使已绑定 role 的声音 ID 自动清空；如服务商声音实际被删除/不可用，该角色在新回合显示“声音不可用”并按规定兜底，用户可回角色设置修复。P1 绑定字段不以列表项 ID 为唯一事实来源。
- 默认 TTS 模型和账号默认声音来源于 §3.4 安全 settings；角色不存 API Key，非法指定不能越权调用其他账号的凭据。
- 原版翻译块只用于展示，实际朗读按旧清洗规则排除 `<translation>` 内容；浏览器朗读无法获得可靠 Web Audio 频谱，使用中性光圈而不是伪随机幅度。


当老记录无法提供 `memory_item_id`，可提交 `selected_text` 与 `source_revision` 作为候选定位输入（替代 item ID，不额外将高敏原文写日志），若无法唯一定位则 409 `STATE_CONFLICT`，需用户明确定位，不能猜测删除。

**永久删除两步操作**：`POST /roles/{id}/deletion-intent` 只获取一次性令牌与 `expires_at`、不实际删除；最终 `DELETE /roles/{id}` 仅能删除已入回收站角色，需令牌和幂等键。完成后 204 无 JSON body，`X-Request-ID` 在响应头，关联私有资源立即禁止访问，学习素材按 §4.3 保留与脱链。

### 5.2 读取会话的完整响应与权限语义

`GET /api/v1/sessions/{session_id}?limit=30&cursor=` → 200：

```json
{
  "session": {"id":"old-session-001","role_id":"cf34568a-7d5e-4f1d-964c-f3ee36cfd2ef","title":"第一次聊天","is_pinned":false,"session_revision":12,"updated_at":"2026-11-01T10:00:00Z"},
  "messages": [
    {"message_id":"efc8f50f-15ae-4b46-b470-86204e123725","ordinal":0,"role":"user","content":"How are you?","created_at":null,"timestamp_source":"unknown","detected_language":"en","turn_id":null,"turn_status":"legacy","audio":{"audio_id":null,"status":"none"}},
    {"message_id":"70d826e9-7b7e-4622-95dc-a72de8c62935","ordinal":1,"role":"assistant","content":"I'm fine.","created_at":null,"timestamp_source":"unknown","detected_language":"en","turn_id":null,"turn_status":"legacy","audio":{"audio_id":null,"status":"legacy_unverified"}}
  ],
  "next_cursor":null,
  "request_id":"req-session-001"
}
```

- 消息 `ordinal` 全会话固定、升序；新消息递增，旧映射不得重新按显示顺序生成 ID；`next_cursor` 用于稳定分页。`created_at:null` 是可预期合法值。`audio` 引用只含受保护的音频 ID/状态，不返回旧无归属可疑 URL。
- 客户端若带 `role_id` 查询参数作一致性校验，服务器必须与 `session.role_id` 比较；不匹配 404。仅 session ID 请求按数据库推导 role，JWT 只说明用户账号、不能说明界面当前角色。
- 用户能管理本人所有角色，但来自角色 A 的会话绝不能被注入到角色 B 的 SOUL/Memory/聊天历史；学习来源并不授予全文访问。
- `PATCH session` 的 `title/is_pinned` 只改提交的字段，写 `session_revision`，消息 append 也递增 revision；若同时编辑，当前客户端需刷新最新 revision 后再提交。`DELETE` 删除会话后学习素材来源按 §4.3 保留/脱链。

### 5.3 聊天回合创建、查询与状态模型

`POST /api/v1/chat/turns` 需要 `client_turn_id`, `role_id`, `session_id`, `text`, `tts_enabled`，可带客户端会话 UI 请求标识，但禁止包含任意私有 role soul/memory 原文。业务接受步骤：

1. 校验 JWT、账号拥有 role 与 session、角色 active、会话非删除、消息格式及大小限制。
2. 用唯一 `(user_id,client_turn_id)` 记录回合、请求规范哈希、attempt=1 与 `user_message_id`；**在正式接受 202 之前持久化 user 消息**，user message 状态 `pending`，同时更新 session_revision。这是短事务；不可先调用模型再存用户消息。
3. 并发处理者 CAS 领取任务，获取服务端当前有效 SOUL、Memory（禁记过滤）、该角色会话的**已完成**消息上下文、翻译/语言设置、当前回合的固定声音快照。外部网络调用不持 SQLite 长写事务。
4. 开始第三方请求前持久化 dispatch 标记；结果成功后优先持久化 assistant 文本/ID，随后决定/执行 TTS；若回合已 cancel requested 或角色/会话已删除，禁止插入 assistant、禁止使音频可访问。
5. TTS 完成后原子置 `completed` 并更新 message.audio / turn 信息；文本成功但 TTS 失败仍 `completed`，带 tts warning。查询回合总是读取持久化状态。

回合持久状态：

| 当前状态 | 事件 | 新状态 | 对外响应 / 不变量 |
|---|---|---|---|
| 不存在 | 合法 POST、写入 user 消息 | `queued` | 202；user_message_id 稳定 |
| `queued` | worker 领取且派发已记录 | `calling_model` | GET 200 / 重复 POST 202；不建新 user 消息 |
| `calling_model` | 模型文本已持久化且需要 TTS | `generating_audio` | GET 200，已有 assistant 文本可以显示“语音生成中” |
| `calling_model` | 模型文本成功且不需要 TTS | `completed` | 200 查询终态，tts.disabled |
| `generating_audio` | 音频就绪或失败/降级 | `completed` | 文本仍有效，tts ready/browser_required/audio_unavailable |
| `queued`/`calling_model`/`generating_audio` | 用户取消，CAS 抢赢 | `cancel_requested` | 200，所有迟到结果无权完成该 turn |
| `cancel_requested` | worker 协作停止/迟到任务被隔离 | `canceled` | GET 200，保持 user 消息为 canceled，assistant/audio 不可供读 |
| `queued`/`calling_model` | 确定失败 | `failed` | 保留 user 消息并标记 failed；只允许明确合规 retry |
| `calling_model` | 已派发但结果可能已发生且不可查询 | `outcome_unknown` | GET 200；不得自动重发付费请求 |
| `completed`/`failed`/`outcome_unknown`/`canceled` | 重复 POST/GET | 保持终态 | 不重新呼叫供应商、不新增消息 |
| `completed` | cancel | `completed` | 返回 200 原终态，客户端仍可本地停止播放，但服务端不删除成功消息 |
| 任何状态 | 角色/会话永久删除 | 逻辑终止、资源不可访问 | 404；迟到结果被丢弃/隔离，不能再创建消息/音频 |

`dispatch_phase` 单独保存 `not_dispatched | dispatched | result_recorded | uncertain`；应用崩溃后，只有**持久记录证明确实尚未发出供应商请求**的 queued attempt 才可安全自动恢复领取。已持久化 dispatched 但无结果时不得盲重放，经过有限安全检查/租约过期后置 `outcome_unknown`。供应商结果已经持久化的，可从 `result_recorded` 继续完成本地 DB/tts 受控处理；若 TTS 下游是否执行未知，不能自动重复付费合成，而是完成文本并显示浏览器朗读/音频不可用警告。

**失败/取消后的用户消息**：始终保留在 UI 对话内并标记 failed/canceled/outcome_unknown，便于用户看见已发送内容；**默认不纳入下一回合模型上下文**，直到该 turn 的合规 retry 成功或者用户显式选择“将这条发送内容视为历史上下文”（后者非 P1 必需，可不提供）。成功 turn 的 user 与 assistant 消息按顺序加入上下文。

### 5.4 请求/响应例子：回合创建、查询、取消

`POST /api/v1/chat/turns`：

```json
{"client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","role_id":"cf34568a-7d5e-4f1d-964c-f3ee36cfd2ef","session_id":"old-session-001","text":"How was your day?","tts_enabled":true}
```

接受后 `202 Accepted`，模型/TTS 仍异步进行，前端通过 GET 查询：

```json
{"client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","turn_id":"edca4c86-925a-4486-9c58-4c0e268252c5","turn_status":"queued","turn_revision":1,"attempt":1,"user_message_id":"063c3b2f-30e4-4c6a-ac3e-0d5383e71dbb","assistant_message_id":null,"role_id":"cf34568a-7d5e-4f1d-964c-f3ee36cfd2ef","session_id":"old-session-001","tts":{"status":"pending","provider_used":null,"warning":null},"request_id":"req-turn-001"}
```

处理中重复 POST（相同 user/client_turn_id/请求体）仍 202，返回同样稳定 turn/user IDs 和最新状态，**不是阻塞等待**。GET `turns/{client_turn_id}` 始终 HTTP 200 返回相同结构、状态更新；正常终态 GET 200：

```json
{
  "client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","turn_id":"edca4c86-925a-4486-9c58-4c0e268252c5","turn_status":"completed","turn_revision":5,"attempt":1,
  "user_message_id":"063c3b2f-30e4-4c6a-ac3e-0d5383e71dbb","assistant_message_id":"ccff4719-3321-46f1-8a4f-b24a96c14c74",
  "role_id":"cf34568a-7d5e-4f1d-964c-f3ee36cfd2ef","session_id":"old-session-001",
  "text":"I'm well. <translation>我很好。</translation>","audio":{"audio_id":"4eac8d65-76ca-4fbd-89c3-11e42877ad3d","url":"/api/v1/audio/4eac8d65-76ca-4fbd-89c3-11e42877ad3d"},
  "tts":{"status":"ready","provider_used":"elevenlabs","fallback_used":false,"warning":null},"request_id":"req-turn-002"
}
```

**确定模型失败**（GET 200 终态，而不是随意返回 500 使客户端重 POST）：

```json
{"client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","turn_status":"failed","turn_revision":3,"attempt":1,"user_message_id":"063c3b2f-30e4-4c6a-ac3e-0d5383e71dbb","assistant_message_id":null,"text":null,"audio":null,"failure":{"code":"MODEL_UNAVAILABLE","certainty":"confirmed_failure","retry_allowed":true},"tts":{"status":"not_started","provider_used":null,"warning":null},"request_id":"req-turn-003"}
```

**下游结果未知**（GET 200，绝不自动重新派发）：

```json
{"client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","turn_status":"outcome_unknown","turn_revision":3,"attempt":1,"user_message_id":"063c3b2f-30e4-4c6a-ac3e-0d5383e71dbb","assistant_message_id":null,"text":null,"audio":null,"failure":{"code":"DOWNSTREAM_OUTCOME_UNKNOWN","certainty":"unknown","retry_allowed":false},"tts":{"status":"not_started","provider_used":null,"warning":null},"request_id":"req-turn-004"}
```

**取消** `POST /api/v1/chat/turns/{client_turn_id}/cancel` 请求：

```json
{"reason":"user_requested","expected_turn_revision":2}
```

取消抢赢则 HTTP 200：

```json
{"client_turn_id":"dad76bed-995d-40eb-bfa1-3ca30726c95e","turn_status":"cancel_requested","turn_revision":3,"cancel_accepted":true,"provider_cancel_guaranteed":false,"request_id":"req-turn-005"}
```

- 如果终态 `completed` 先提交，则 cancel 返回 HTTP 200 `{turn_status:"completed",cancel_accepted:false,provider_cancel_guaranteed:false,request_id:...}`，不回滚消息。浏览器本地停止播放不需等待服务器响应。
- 如果请求的 expected_turn_revision 已过期且状态仍活动，则 409 `REVISION_CONFLICT`；前端 GET 当前状态再提示，不得重发不带版本的取消修改。
- 取消后即使下游模型返回，提交 assistant 或音频前再次检查 cancel tombstone 和角色/会话存续，迟到结果不准复活；在取消之前已完成并提交的文本/音频按“completed 先赢”处理，不静默删除已有成功历史。

### 5.5 明确 retry 与状态边界

`POST /api/v1/chat/turns/{client_turn_id}/retry`，**新操作幂等键**，请求：

```json
{"expected_attempt":1,"reason":"user_explicit_retry"}
```

- 仅 `failed` 且 `failure.certainty∈{not_dispatched,confirmed_failure}`、`retry_allowed=true` 时可进入新的 `queued` attempt 2；**相同 client_turn_id、原 user_message_id、原请求文本哈希不变**，新 attempt 的 `attempt_id`/次数递增，禁止重复添加用户消息；同一 retry 操作键重放返回同 attempt 的持久状态。
- `outcome_unknown`、`completed`、`canceled`、已删会话、角色回收站等返回 409 `STATE_CONFLICT` 或 404；不能以相同 client_turn_id 擅自“再试一回”。若用户选择接受可能重复计费，需**显式发起新的独立聊天 turn**（新的 client_turn_id）并告知可能重复，绝不由自动网络 retry 触发。
- `failed` 的旧结果仍保存在尝试审计中，但当前 turn 顶层状态会在用户显式 retry 后转换为 queued；UI 显示尝试历史/重试标识，保持原 user 文本。提供 `max_attempts` 配置上限，禁止无限打第三方；每次付费请求前核验用户许可/限额。
- 结果确定失败但第三方仍可能计费，UI 不保证零费用。HTTP 请求传输超时，若本地无法证明未派发，则查询状态并标 unknown，禁止“重试按钮”绕过安全策略。

### 5.6 模型系统指令、顺序与权限

模型提示由后端按 `JWT user_id → role_id → session_id` 验证并加载当前角色的 SOUL、经过禁记过滤的 Memory、账号语言/翻译设置。只使用该角色已完成的历史消息；前端任意传来的 SOUL/Memory 文本不能覆盖服务端真值。翻译块显示沿用旧格式，TTS 输入剔除 `<translation>` 标签块；消息正文在 HTML 渲染前做净化。

### 5.7 原生声音合成、播放与取消真值表

**声音绑定**见 §4.7。完整 LLM 文本先完成后进行服务器 TTS，不引入流式回复。`tts_enabled` 是**合成许可**；`tts.is_muted` 以及聊天的本地 mute/stop 是**播放许可**，二者不能混为一谈。

| 用户/系统条件 | 服务端可否开始合成 | 可能的 `tts.status` | 客户端动作 |
|---|---|---|---|
| 请求开始 `tts_enabled=false` | 否 | `disabled` | 不自动浏览器朗读，不播放 |
| 请求开始允许合成、账号未静音 | 是 | `ready` / `browser_required` / `audio_unavailable` | ready → 认证取音频后按浏览器许可播放；browser_required→经许可朗读 |
| 请求开始允许合成，但默认静音 | 是（可由前端进一步选择禁合成以省费） | `ready` 等仍合法 | **不自动播放**；保持可点的播放入口 |
| 生成中点击静音 | 已派发的合成未必能停 | `ready` 仍合法 | 阻止任何迟到自动播放、停止当前音频 |
| 生成中点击停止 | 尽力取消，不保证下游已停或无费用 | `ready`、`cancel_requested`、`canceled` 视竞争决定 | **本地立即停止** HTMLAudio/speechSynthesis/字幕/录音；迟到回包不得恢复播放 |
| 手动点击“播放” | 不默认重合成 | `ready` 或既有降级状态 | 此次用户操作视为**一次明确的播放许可**；只播放授权的资源 |
| 浏览器拒绝自动播放 | 不重新调用其他通道绕过权限 | `ready` / `browser_required` | 保留点击播放入口与提示，不能绕过 autoplay 限制 |
| ElevenLabs 失败但 Edge 成功 | 可按服务端约定依序兜底 | `ready`, `provider_used=edge`, `fallback_used=true`, warning | 正常显示回复，使用 Edge 音频驱动原版频谱 |
| 服务端音频失败，浏览器朗读可用 | 不再自动付费重发 | `browser_required` | 经用户/浏览器播放许可朗读；中性光圈，无假频谱 |
| 全部音频不可用 | 否 | `audio_unavailable` | 保留文本与翻译，提示“仅文本可用” |

`tts.status` 枚举：`not_started | pending | ready | browser_required | audio_unavailable | disabled | canceled`。`provider_used∈elevenlabs|edge|null`，warning 不含密钥、供应商原始响应。**ready 代表音频已持久化且可依法读取，不保证 HTMLAudio 播放成功**；客户端还有独立播放状态 `idle/loading/playing/paused/ended/failed/stopped`，禁止将 `audio:null` 一律视为需要浏览器朗读。

音频访问：`GET /api/v1/audio/{id}` 成功返回 `audio/mpeg` **二进制**、受保护的 Cache-Control、`X-Request-ID`；前端可认证 fetch→Blob→短期 object URL 接入旧全局 HTMLAudio，并在停止、角色/会话切换和不再使用时 revoke URL。另一可选路线是服务端受限签名 URL，须在实现时额外验证泄漏与过期。**临时 Blob URL 不是要持久化在 ChatMessage 中的音频地址**。历史不明归属 audio_id 不允许公开裸读。

前端会话/角色/账号切换时，所有异步模型、录音、播放、字幕回调带账号+role+session+turn 上下文标签；过期回调不改变当前 UI；本地先停止再发送服务端取消，防音频穿越角色。模型结果可以保留在原会话，但不能跨页面注入；角色/会话已永久删除时服务端也不让它写回。

## 6. 学习模块：语言、选词、收藏与导入协议

### 6.1 范围和语言字段

- 共享词库属于 `user_id`，不属于某个角色。角色学习模式 `study_enabled=false` 是默认值，角色详情和聊天顶栏图标只修改当前角色的同一字段；关闭后隐藏学习收藏交互，不能影响翻译、TTS、聊天内容。
- `GET /api/v1/learning/languages` 返回 `{items:[{language_code,display_name,enabled,words_count,sentences_count}],supported:[{language_code,display_name}],request_id}`；`POST` 只从服务端支持的列表启用语种。使用 BCP-47 语言代码（例 `en`,`ja`,`de`）；**P1 支持添加/移除语言**，不仅固定三项切换。删除语言若有素材需二次确认，不允许影响其他语言；单纯清空词库仅清词，不删除语言或句子。
- `VocabularyEntry.status∈new|learning|mastered`，仅用户手动改；初始为 `new`，不能用 AI 猜测掌握情况。`word_revision` 比较和更新原子进行。
- **选词语言**不依赖学习中心当前选中的语言。聊天选中源消息时，服务端返回/验证 `message.detected_language`（可以 `null`/`und`），前端允许用户校正 `language_code`；语种不明确时**必须由用户显式选择**后保存。原文与翻译选区要标明 `selection_surface∈original|translation`，默认只从原文加词，选翻译时弹出语言确认；服务端根据原消息与选择文本校验，不接受任意跨角色拼接。

### 6.2 保存词和收藏句子

`POST /api/v1/learning/words` 手动输入例子：

```json
{"language":"en","term":"sidetracked","meaning":"分心；耽搁","example":"I got a little sidetracked.","source_message_id":null}
```

从对话选词的请求可带 `source_message_id`, `selected_text`, `selection_surface`, `selected_context`（仅选中句子上下文，不能无界抓取全部消息），服务端从消息推导实际 role/session 并校验其存在与归属。**不允许客户端同时提交不匹配的 `source_role_id`、`source_session_id` 来伪造来源**；若同时传作一致性核对，任一不匹配返回 404。非聊天手动词 `source_status:"manual"`。

同账号同语言词的 `(user_id,language,normalized_term)` 唯一；新增返回 HTTP 201 `result:"created"`；重复返回 HTTP 200：

```json
{"result":"skipped_duplicate","existing_id":"fc899f28-f574-47eb-9884-e9fa73e93488","request_id":"req-word-001"}
```

重复不修改原 `meaning/status/example/source/created_at/word_revision`。归一化规则：Unicode NFC + 裁剪首尾空白、重复内部空白归一；英语不区分大小写，其他语言按其语言规范单独处理，绝不能统一把日语等 lower-case 当作充分规则。

句子 POST：`language,text,translation?,source_message_id?,selection_surface?`；同账号+语言+NFC/连续空白规整后的 `normalized_text` 唯一；重复 200 `skipped_duplicate`，不改旧来源/翻译/创建时间。句子文本只保存用户**主动收藏的完整句子或选择片段**，不会因为学习开关开启自动把全部聊天上送词库。删除会话和角色后按 §4.3 脱链。

`PATCH /api/v1/learning/words/{id}` 示例：

```json
{"expected_revision":3,"status":"mastered"}
```

成功 200：`{"word_id":"...","word_revision":4,"status":"mastered","request_id":"..."}`。冲突 409，保留前端改动草稿。手动删除词是明确选择单条记录；清空语言词库与删除语言必须独立二次确认。账号共享不意味着任意角色能读取其他角色的私聊或禁记内容。

### 6.3 导入的解析、上限与预览

- 支持手动单词、批量粘贴、TXT、CSV。`format:"paste"` 的 JSON 文本或 `multipart/form-data` 上传 TXT/CSV，服务端必须限制单文件 ≤ 1 MiB；总量 ≤ **5000 条解析后的逻辑记录**，不是按换行符粗略计算（CSV 引号字段内允许换行）。单词 ≤ 128 字符，释义 ≤ 1000 字符，编码 UTF-8/UTF-8 BOM，CRLF 可读；CSV 应按 RFC 4180 解析引号、逗号与多行，不能用 `split(',')` 实现；不支持编码返回清晰错误，不猜测乱码。
- TXT 一行一词或 tab 分隔释义；粘贴一行词或按明示格式 `词,释义`。标准 CSV 以实际列定义读取（如 `term,meaning` 表头可识别）；字段不合法标 invalid，并指出逻辑行号和错误原因。CSV/Excel 公式风险仅当将文本导出时进行防注入，不把前导 `=` 意味着“执行公式”。
- `POST /api/v1/learning/import/preview` **不写词库**，创建不可变 `preview_id`、解析后每行 `row_number`、`status∈valid|duplicate|invalid`、`reason`、`term/meaning` 与 15 分钟 `expires_at`。预览属于账号且绑定语言、内容指纹、行号及当前词库去重快照；commit 时再次真实去重，防止其他设备已经插入同词。

预览请求（JSON）：

```json
{"language":"en","format":"paste","text":"hesitate,犹豫\nencounter,遇见\n,缺少词语"}
```

预览响应（200）：

```json
{
 "preview_id":"add86ca9-d16f-4b05-93a4-9c93c263c42e",
 "expires_at":"2026-11-01T10:15:00Z",
 "stats":{"valid":2,"duplicate":0,"invalid":1},
 "rows":[
  {"row_number":1,"term":"hesitate","meaning":"犹豫","status":"valid","reason":null},
  {"row_number":2,"term":"encounter","meaning":"遇见","status":"valid","reason":null},
  {"row_number":3,"term":"","meaning":"缺少词语","status":"invalid","reason":"EMPTY_TERM"}
 ],"request_id":"req-preview-001"
}
```

### 6.4 Commit：选区、一回消费与幂等结果优先

`POST /api/v1/learning/import/commit`，header `Idempotency-Key: <UUID>`，正文：

```json
{"preview_id":"add86ca9-d16f-4b05-93a4-9c93c263c42e","selected_row_numbers":[1,2]}
```

**服务端顺序必须为：**

1. 校验账号+操作+幂等键，**先查询已完成记录**，同键同请求体已有成功 → 直接返回原结果，**即使预览现在过期**；同键不同正文返回 409 `IDEMPOTENCY_CONFLICT`。
2. 尚无成功重放记录时才验证 preview ownership、未消费、expires_at 和行号范围；过期/已被其他成功提交消费返回 409 `STATE_CONFLICT` 且零写入。
3. `selected_row_numbers` **省略** = 预览中全部 `valid` 行；显式 `[]` = 422 `VALIDATION_ERROR`（没有选中任何行）；有重复行号、非整数、越界、选择 `invalid/duplicate` 行 = 422，**不能默默改变选区**。客户端必须先调整选择。
4. 一个 `preview_id` 在 P1 只能被**一个成功的 commit** 消费；之后同键同正文按步骤 1 重放，不同键无论是否相同选区都返回 409 `STATE_CONFLICT`，用户需重新 preview。
5. 在 DB 事务中对实际词库做唯一键去重并写入有效新词；其他设备刚插入同词则跳过，不覆盖旧释义/状态/来源。commit 与幂等结果及 preview 消费状态同事务成功，避免“写进词库却忘了 commit 成功”的本地双写窗口。
6. HTTP 200 返回完整固定结果，其中原预览选区、创建和重复统计、稳定 `created_word_ids`：

```json
{"result":"committed","created":2,"skipped_duplicate":0,"invalid":0,"created_word_ids":["ad67c300-8ae9-4314-83b1-16806b544a5f","22cfaa0a-cf21-4520-89fb-9cd0ab8c588e"],"request_id":"req-commit-001"}
```

对重复网络包，返回同一结果，不以“预览已消费”覆盖旧成功。对过期预览未成功提交的返回 409，保留用户原输入供重新 preview。对 malformed CSV、超限、非法行/语言，前端展示具体原因，不能假装一部分保存成功而不标记失败。

## 7. 安全、隐私、历史音频与错误防护

1. **身份**：所有新 API 要 JWT；生产环境禁用弱 JWT_SECRET 默认值，密码验证/会话不泄露 SQL 堆栈；Token 所属 user_id 为唯一账号归属根，角色/会话/消息/音频/词句均验证账号链。不存在和越权对外统一 404，授权前不能泄漏标签、昵称、SOUL/Memory、消息摘要。
2. **密钥**：LLM/ElevenLabs 凭据仅在服务端认证用户对应槽访问；安全 GET 只返回 `credentials.<slot>.configured`，不能让前端通过读明文检查配置；PUT/DELETE 版本 CAS，失败不清空已存 Key。旧 JS localStorage 的 Key 清理须等迁移成功验证，不将浏览器本地 Key 或真实凭据放入任何设计文件、日志、Git、原型数据。
3. **供应商映射**：LLM 下游 401/403/429/5xx 由服务端转换为 `PROVIDER_AUTH_FAILED/PROVIDER_QUOTA_EXCEEDED/RATE_LIMITED/MODEL_UNAVAILABLE` 等**供应商类错误**；不得触发前端登出本地账号。原始供应商响应可能带可识别数据，日志只存代码和脱敏摘要。
4. **历史音频**：旧 `audio_files` 无可证实 `user_id/session_id` 所有权时，不能通过 `GET /api/audio/{id}` 公共裸读。审计能安全回填关联则按新音频服务保护；不能证明归属时标记 `legacy_unverified`、新界面不可播放/需说明，不能通过猜测文件路径绕开授权。新音频始终绑定 user/role/session/message，历史引用可被隔离但不能误归给错误账号。
5. **有界并发与成本**：限制每账号同时进行的第三方回合数；同键重复请求不会再次派发；`outcome_unknown` 不自动重发；下游呼叫成本仍可能发生。自动 Memory/SOUL 任务有限队列和频率，不因反复失败无限调用模型。
6. **禁记与备份**：高敏信息（Key、证件、银行卡、私密影像、具体医疗资料等）不进入长期记忆、候选日志和交接证据；禁记过滤优先于历史恢复和灾备恢复。备份在授权环境安全存放、限定权限，不入 Git、不随附件分享。旧快照恢复后必须补齐后续禁记规则，否则保持只读。
7. **静态内容安全**：聊天 HTML/Markdown 做可信净化；上传头像/CSV 校验类型/大小/内容，CSV 导出时防公式注入；不能直接在 HTML 原型内固化真实密钥或用户聊天。CORS、CSRF/跨站请求与 Cookie/Bearer 使用方式应按现有部署模型做安全测试。
8. **状态日志**：可记 `request_id`, route, status, actor_type, entity_id 的最小化哈希, latency, revision 变更信息；禁止原始聊天、SOUL、Memory、voice output、API Key、授权头与音频内容。只读审计回执可展示数量与非可逆摘要而不展示正文。

- 会话 GET 读服务端实际 revision/消息分页，禁止凭当前空本地列表全量覆盖服务器。保存失败显示失败并保留草稿；流转中 `turn_status`/`tts.status`/`audio playback state` 各自显示，不将一切 null audio 当作 browser fallback。
