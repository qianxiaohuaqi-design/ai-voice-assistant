## A. P0 总目标、成功标准与完成边界

**唯一目标：在不丢失现有设置、Key、声音库、会话和原始消息的前提下，阻止危险整包同步写入，并提供可验证的安全局部 settings/credentials 管理和稳定的前端初始化/保存反馈；具备经授权的隔离备份与恢复证据。**

P0 **不是**角色开发、Memory 迁移或正常聊天恢复。P0 完成后旧聊天默认仍处于**可解释的只读维护状态**，只有后续默认角色/旧会话映射 + 持久 turns 验证通过、并经另行授权，才可以开放真实发送。

**P0 通过必须同时满足：**

1. 受保护环境和工作区所有既存资产被识别、未被全量 checkout/clean 覆盖；审计前后清单及业务文件哈希与本轮改动可解释。
2. 每个拟触达数据库环境已经获得单独许可，形成可恢复的一致性备份；**隔离副本恢复测试通过**，并有原始账号/会话 ID 集合、原消息摘要和 schema 校验，真实数据不泄漏。
3. `POST /api/user/sync` 无论请求是否含全列表、自带标头或遗漏字段，均在**任何业务更新前**安全拒写；Key、设置、声音库、会话都零变化。
4. 旧 `/api/chat` 在没有安全持久会话写入口的过渡期**不调用第三方模型/TTS**，返回维护状态；用户不能“看似正常聊天但实际丢记录”。
5. 新 `GET/PATCH /api/v1/settings`、凭据专用 PUT/DELETE 均遵守 `settings_revision` CAS、字段白名单、Key metadata；旧 Key 不能因保存主题或清理浏览器缓存而消失。
6. 前端 hydrate 阶段绝不发危险同步，失败时不写空缓存，HTTP 失败不报保存成功。
7. 全部隔离测试与恢复演练断言通过，并且异常情况下保持/恢复到**安全拒写**状态，不得因回滚重新开放危险旧同步。

## H. P0-04 旧同步全事务防护及聊天维护状态

**目的：** 关闭现有能误删/覆盖用户数据的入口，用户不能继续“正常发但实际不保存”。

**拟改文件：** `web_app.py` 的 `POST /api/user/sync`、`POST /api/chat` 入口与相关错误处理中间件/配置；必要的维护状态 GET。此阶段不更改第三方模型/TTS 的正常实现细节。

**数据库影响：** 拒绝旧整包写入时**零**写入（Key、设置、声音库、会话、时间戳、revision 均不变）；旧聊天被维护拒绝时不创建音频，也不调用供应商。

**冻结策略：**

- `POST /api/user/sync` 在设置和会话所有写语句之前统一返回 409 `SYNC_UNSAFE`；不接受自带 `If-Match`、`X-Sync-Mode` 或任意 `sessions=[]` 的 full-replace 旁路。
- `POST /api/chat` 在安全 turn 服务未上线前默认 423 `READ_ONLY_MAINTENANCE`，**必须在任何模型/TTS 下游调用之前拒绝**。现有系统不提供会话持久写入口，不能开放“只聊不存”的假成功路径。
- `GET /api/user/sync` 的兼容读由 P0-05 的安全切换策略决定；不能在关闭旧写时无计划地把仍依赖明文 Key 的老 JS 改成空值并继续让它聊天。旧缓存 JS 不会自动理解新的错误，因此服务端拒写是最终兜底，维护 UI 仍需 P0-06 接入。

**测试（使用虚构数据）：**

1. 设置包括非空 Key、voice list、3 会话；对旧 sync 提交 `{}`、省略 sessions、空 sessions、全量 sessions、自制完整标头 → 全部 409，设置/Key/列表/消息摘要 0 变化。
2. 模拟启动首次 `setTheme` / hydrate 内 `setTheme` / `saveSessions` → 服务器不删除会话。
3. 维护模式调用 `/api/chat` → 423，模型/TTS mock 调用次数 0；且应有用户可读的维护原因。
4. 模拟旧缓存客户端不检查 response.ok：即使 UI 可能误显示成功，服务器仍必须数据零变化，**不能把这当旧 UI 通过**。

**停止条件：** 任一旧 POST 仍能改 Key/设置/会话、旧 chat 仍能发真实请求、保全路径未验证、错误处理泄漏堆栈/凭据。

**回滚：** **不得**回退为危险全量写。若新设置出现问题，保留 `SYNC_UNSAFE` 与聊天 `READ_ONLY_MAINTENANCE`，先隔离/正向修复；不以“恢复旧用户体验”为由重新开放旧 POST。

## I. P0-05 局部 settings、凭据槽与明文缓存切换

**目的：** 允许安全修改设置而不动会话和其他字段，并消除新页面对服务端 API Key 明文读取的依赖。

**拟改文件：** `web_app.py` 的 `/api/v1/settings` 与 credential 路由、`models.py` 的 revision/必要存储映射、相关测试；复用现有真实用户配置字段。P0 不要求新建每厂商独立凭据系统。

**新响应/字段形状：** 严格按 T1 v1.1 §3.4：`model.{chat_model,base_url}`，`tts.{provider,voice_id,elevenlabs_model,edge_voice,is_muted,custom_voices:[{id,name}]}`，`translation.{response_language,enabled,target_language}`，`appearance.ui_theme`，`credentials.llm_primary.configured / credentials.elevenlabs.configured`，`settings_revision`。`llm_primary` 是历史通用模型 Key **槽**，不是 Anthropic 公司专用。`custom_voices` **新接口数组、旧库 JSON 字符串**；非法旧值先留存/报告，不静默清空。

**写入规则：**

- PATCH 只更改明确白名单字段；省略=不动，`null/""` 见 §2.3；未知字段 422。任意 PATCH 不接受 sessions，不回 Key。
- 凭据仅 `PUT/DELETE /api/v1/settings/credentials/{llm_primary|elevenlabs}`，非空 PUT；撤销用 DELETE 且用户明确确认。和其他 settings 使用同一 `settings_revision` 并发事务 CAS。
- model fetch / chat 侧的 Key 从认证 user DB 槽安全解析，不依赖前端再次传 Key 或读取 masked 字符串；配置 metadata 必须反映真实存在的 Key。服务端日志及响应不得含 Key 明文。
- 新前端读取 `configured`，**只有确认服务端配置已保存且真实路由支持 metadata 时**才清理旧 browser localStorage Key 缓存及逻辑；失败停维护并请求用户修复，不自动删 DB 已存 Key 或丢失唯一浏览器缓存值。
- 旧 `GET /api/user/sync` 明文兼容应通过可控切换结束，目标为旧 GET 返回 426 `CLIENT_UPGRADE_REQUIRED`；具体时机由部署/客户端切换的单独批准决定；旧 POST 永远拒写。不能因旧 JS 缓存仍在就永久泄露 Key。

**验收断言：**

- GET 响应字符串中无任意实际 Key；configured 路径准确。
- PATCH `appearance.ui_theme` 只修改主题和 settings_revision；旧 Key、模型、翻译、voices、sessions、消息 SHA 均不变。
- PUT 更换 llm_primary Key 不碰 elevenlabs Key；DELETE 单一槽不影响其他槽，settings_revision 递增。
- 双设备同 revision 竞争只有一方 200，另一方 409；无版本 428；空 Key 422。
- GET → 改主题 → PATCH 不会覆盖服务端密钥；旧自定义 voices 字符串成功解析为新数组，保存其他字段不会把解析失败的列表清空。

**停止条件：** 发现任何明文 Key 回传/日志泄漏、settings PATCH 会隐式覆盖未传字段、缺乏 CAS、声音库异常被误清空、旧客户端自动上送空 Key 或客户端切换尚未安全。

**回滚：** 保留旧 sync 拒写；局部 settings 可关闭写窗口并保留服务器旧值；需要改 DB/Key 时只按经过授权的恢复/正向修复执行，绝不从浏览器 localStorage 猜测旧 Key 来覆盖服务器。

## J. P0-06 原生前端 hydration、局部保存与失败提示

**目的：** 真实界面不再触发危险空列表同步，用户能区分“本地改了”和“服务器确认保存”。

**拟改文件（仅在已有授权范围内）：** 原版 `static/index.html`、实际被引用的 `static/js/app.js`、`static/css/style.css`，及最小本地测试文件；优先保留未跟踪文件原始状态，避免整包拷 V5.2。若其他 JS 入口被实际启用，以运行入口审计为准，不盲改不被加载的文件。

**必须修复的三条已知危险路径：**

1. **首次 `setTheme()`**：只更新视觉，不触发整包 session/settings POST；在 `hydrating` 禁止保存。
2. **hydrate 内部调用 `setTheme()`**：恢复界面设置不等于用户主动保存；不得提交空 sessions。
3. **`saveSessions()`**：不再走危险全量 sync；在 P0 聊天写维护期其写入口明确不可用，并提示不可保存，不偷偷缓存成“成功”；后续 P1 turns 启动后由正式会话写 API 代替。

**状态/提示：** `hydrating → ready | load_failed | unauthenticated`；GET 失败不把 localStorage 空值上传服务端；未确认 2xx 不显示“已同步”；网络失败、401、409、422、428、500 均展示可理解的失败提示，保留用户未保存输入。个性化（主题）与系统设置（API/TTS/翻译/声音库）仍是不同 UI，虽共享 settings 后端资源。

**UI 与音频保护：** 只改必要的加载与保存调用，不覆盖真实星云/WebAudio/字幕/麦克风；在维护窗口清楚说明聊天禁用，并保持可读旧会话与导出/备份能力（如后续另行授权）。V5.2 仅作交互参考。

**验收断言：** 模拟网络断开、非 2xx、先 theme 后 settings GET、异地 revision 冲突、hydrating 初始空 sessions；后台所有数据未被删除；成功提示只有 2xx；原版 UI DOM/Orb 引用未被错误替换。

**停止条件：** 发现某一新前端代码仍会自动调用旧 POST、无法控制旧 Key 缓存危险路径、主题切换破坏 Orb、界面在维护时仍显示可发送成功。

**回滚：** 前端可回到**安全的维护界面**，不得把仍调用危险旧 POST 的缓存 JS 作为恢复目标；服务器门禁常开。失败时禁用设置写与聊天写，保留原始本地用户草稿直到用户决定。
